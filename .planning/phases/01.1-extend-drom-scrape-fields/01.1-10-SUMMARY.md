# Phase 01.1 Plan 10: Cookie-Strip beforeRequest Hook (Gap 1 Closure) Summary

**One-liner:** `STRIP_COOKIES = new Set(['npsPayload','npsType','showNPS'])` denylist + got `hooks.beforeRequest` entry strips three drom NPS widget cookies from the outgoing `Cookie` header before each request, preventing nginx HTTP 431 on long BMW catalog crawls.

## What Was Built

Added a `beforeRequest` hook to `dromClient` in `server/scrapers/shared/http.ts` that strips exactly three drom feedback-widget cookies (`npsPayload`, `npsType`, `showNPS`) from the outgoing `Cookie` header on every request. The fix is targeted: the cookie jar (`tough-cookie`) is untouched, only the header projection changes. Affinity and region cookies (`ring`, `segSession`, `PHPSESSID`, `cookie_cityid`, `cookie_regionid`, `my_geo`, `dr_df`, `veryFirstHit`) continue to flow untouched.

Root cause: `npsPayload` is a base64-encoded component ID list that drom's NPS widget appends on every `/catalog/*` page visit. Across a 1h28m BMW sweep (~2000 trims), it grew to ~8KB and triggered nginx `large_client_header_buffers` limit, producing HTTP 431 `Request Header Fields Too Large`.

## Deviations from Plan

None — plan executed exactly as written.

The test approach was verified live: when `dromClient` (which has `cookieJar`) receives a request with an explicit `cookie` header AND the jar is empty for that URL, got passes the explicit cookie through to the `beforeRequest` hook. The hook sees the full explicit cookie string including `npsPayload` etc., strips the bloat names, and the filtered string reaches the server. This is the correct RED/GREEN pattern.
