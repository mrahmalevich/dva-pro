<decisions>
## Implementation Decisions

### Resume granularity (cursor)

- **D-01:** Cursor extends to per-trim resolution. Add `lastComplectationIndex: number | null` to `cursor.json` next to existing `lastBrandSlug` / `lastModelSlug`. On resume mid-generation, the per-comp loop skips already-fetched trims using the saved index. Worst-case refetch on a fresh resume is the trim that was in flight when the run died (≤ 1 page).
- **D-02:** Cursor write cadence is **every trim** (no throttling). The BMW pilot's ~2 000 trim writes are cheap (`writeFileSync` on a sub-1KB JSON), and the simpler invariant is worth the trivial I/O.
- **D-03:** Crossing into a new generation resets `lastComplectationIndex` to 0 (or `null`); the existing `CursorSchema` (Phase 01-11) extension must remain backward-compatible — a cursor written by Phase 01 (without the index) loads as `lastComplectationIndex = null` and the per-comp loop starts from 0.
- **D-04 (open for planner):** Whether `lastGenerationSlug` also needs to enter the cursor schema (today the cursor stops at brand+model — but the per-comp loop iterates trims of multiple generations within one model). Planner decides during plan-phase based on a closer read of `drom/index.ts`.

### Coverage metric formula (`report.json.field_coverage[group]`)

- **D-05:** Per-trim, majority-threshold formula. For each trim, a group is "covered" if **≥ ⌈2/3 × leaf_count⌉** of its leaves are non-null. The group's coverage is `count(covered trims) / total_trims`. Gate: each of the six groups ≥ 0.70 across the BMW pilot.
- **D-06:** Threshold table (precomputed; planner / verifier hardcodes from this list — no runtime ceil math):
  - Identity (7 leaves)   → ≥ 5 non-null per trim
  - Pricing (2 leaves)    → ≥ 2 non-null per trim (effectively all)
  - Drivetrain (6 leaves) → ≥ 4 non-null per trim
  - Dimensions (9 leaves) → ≥ 6 non-null per trim
  - Comfort (6 leaves)    → ≥ 4 non-null per trim
  - Tires (2 leaves)      → ≥ 2 non-null per trim (effectively all)
- **D-07:** Pricing and Tires both collapse to "all leaves required" because ⌈2/3 × 2⌉ = 2. This is intentional — for these two-leaf groups, partial extraction is not informative. If tire extraction in practice falls below 70% of trims, the planner should surface this as a SPEC.md adjustment request rather than silently weakening the formula.
- **D-08:** `field_coverage` lives in `report.json` as a top-level object next to existing `image_failure_rate`. Snapshot golden (`bmw-pilot.test.ts.snap` per SPEC R-8) locks the six rates rounded to 2 decimal places.

## Existing Code Insights

### Reusable assets

- `server/scrapers/drom/parse-generation-page.ts` — cheerio + zod parser pattern. Per-comp parser reuses the same shape: cheerio.load, targeted selectors, zod validation at the end. Difference for Phase 01.1: zod failures emit null leaves instead of throwing (per SPEC R-6).
- `server/scrapers/shared/types.ts` — `ModelRecord` zod schema. Add `Complectation` zod sub-schema in the same file. The `kind: 'parse'` discriminator on `report.errors[]` (added Phase 01-14) is the slot for per-comp parse failures.
- `server/scrapers/shared/cursor.ts` — `CursorSchema` + `CorruptCursorError` (Phase 01-11). D-01..D-04 above extend this schema with backward-compat preserved.
- `server/scrapers/shared/http.ts` — `pLimit(1)` + `sleep` (fixed delay). Probe-down rate limiter (SPEC R-5) replaces the fixed-delay branch. Existing block-detection module remains unchanged.
- `server/scrapers/shared/report-html.ts` — Per-run viewer (Phase 01-15, 531 LOC). Extension surface: render nested `complectations[]` per `ModelRecord`. Must remain self-contained (no external network at view time — same constraint as 01-15).
- `server/tests/__snapshots__/report-html.test.ts.snap` — Snapshot pattern already established by Phase 01-15. Phase 01.1 adds `bmw-pilot.test.ts.snap` (coverage rates) and `bmw-pilot-viewer.png` (rendered viewer image) under the same `__snapshots__/` directory.

### Established patterns

- **Throw-loudly vs emit-null:** Phase 01 chose throw-loudly for catalog parsers (Pitfall 1). Phase 01.1 inverts this for per-comp parsers (SPEC R-6 — no must-have fields). Boundary lives at the `parseComplectationPage` function: it must catch its own zod failures and per-section extraction errors, returning a record with null leaves and a `_extraction_errors[]` annotation.
- **Brand filter:** No existing pattern for "scrape only some brands". Plan-phase introduces an explicit brand allow-list (e.g., `BMW_PILOT_BRANDS = ['bmw']`) in the orchestrator, gating the per-comp fetch loop. Other brands' generation handling is unchanged.
- **Image counter-drift gate (Phase 01-14):** Provides the template for "tolerant per-record fetch with bounded abort". Per-comp fetches reuse the same `kind: 'parse'` error discriminator; the orchestrator does NOT add a new abort gate for per-comp failures (every failure emits a record with null leaves, never aborts).

### Integration points

- `server/scrapers/drom/index.ts` (orchestrator) — between `parseGenerationPage` and the next-generation iteration: insert per-comp loop. Cursor write per trim. BMW brand filter wraps the loop.
- `server/scrapers/shared/types.ts` — single source of truth for `Complectation` zod schema; export from there for downstream Phase 03 importer.
- `server/scrapers/shared/report-html.ts` — extend the model-card renderer to accept and display `complectations[]` (renderer signature change OR new sub-renderer; planner picks).
- `data/scraped/SCHEMA.md` and `data/scraped/README.md` — both updated by 01-15. Add a per-complectation field-group reference.
