## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → drom.ru | Operator-initiated outbound HTTPS to a public Russian site (existing posture from Phase 01); no PII exchanged; same windows-1251-decoding path as the live scraper |
| operator argv → cli.ts → fetchHtml | New surface: `process.argv[4]` (compId) is interpolated into a URL path; mitigated by the `/^\d+$/` regex gate |
| npm registry → ~/.cache/puppeteer/chrome/ | New supply-chain edge: `pnpm install` triggers a Chromium download from Google's CDN via puppeteer's postinstall script |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01.1-01 | Tampering | server/scrapers/cli.ts (compId argv) | mitigate | Regex `/^\d+$/` on `process.argv[4]` rejects any non-numeric input before URL interpolation; prevents path traversal (e.g., `../../../etc/passwd`) and URL injection (e.g., `207354@evil.com`). Verify via `grep -c "/\\^\\\\d\\+\\$/" server/scrapers/cli.ts` returning 1. |
| T-01.1-02 | Spoofing / DoS | drom.ru | mitigate | Operator runs `--capture-fixture` exactly 3 times in this plan; each call is rate-limited by the existing fixed 10s `politeDelay()` from Phase 01 (probe-down replacement is Wave 1, not yet active here). Total outbound: 3 requests in 30+ seconds. Below any reasonable rate-limit threshold; well under Phase 01-VERIFICATION's polite-delay budget. |
| T-01.1-03 | Information Disclosure | server/tests/fixtures/drom/complectation/*.html | accept | Captured HTML is from `https://www.drom.ru/catalog/bmw/x5/<id>/` — public catalog data with no user content, no auth-gated pages, no PII. Drom catalog has no per-user sessions; the HTML body is identical for all visitors. Committing it to the repo replicates public information already on drom's CDN. |
| T-01.1-04 | Denial of Service | drom.ru via puppeteer download | mitigate | Puppeteer downloads Chromium from `storage.googleapis.com`, NOT from drom. The 280 MB download impacts Google's CDN, which is built to absorb npm-scale traffic. No drom-side DoS exposure. |
| T-01.1-05 | Elevation of Privilege | puppeteer postinstall script | mitigate | Puppeteer is added to `devDependencies`, not `dependencies`. Runtime production images (Phase 03+) do NOT run `pnpm install --prod`-with-dev; the postinstall does not execute on production. Dev-machine and CI exposure is limited to the postinstall fetching the Chromium binary from googleapis (a Google-signed binary, content-addressable by SHA in puppeteer's `chrome-versions.json`). Verify via `grep -c "chrome-headless-shell\\|chrome-versions" node_modules/puppeteer/package.json` returning ≥ 1 after install. |
| T-01.1-06 | Tampering / Supply chain | pixelmatch + pngjs | accept | Pixelmatch is the same library Playwright uses internally [CITED: testingbot.com]; ~150 LOC, zero transitive deps. Pngjs is pure-JS with one transitive dep. Both are dev-only and never ship to runtime. |
| T-01.1-07 | Information Disclosure | broken-truncated.html (mid-tag truncation) | accept | The truncation point is byte 50000, well after the HTTP headers/cookies that drom strips before serving HTML body. No session token surface exists in catalog HTML. |

**Severity ≥ high:** none. All threats are LOW-MEDIUM and either mitigated by existing controls (regex gates, devDep separation) or accepted with documented rationale.
