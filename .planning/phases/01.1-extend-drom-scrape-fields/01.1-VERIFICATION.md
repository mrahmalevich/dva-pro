## Gaps

### Gap 1: BMW pilot HTTP 431 — cookie-jar bloat blocks SPEC R-7 verification

**Status:** RESOLVED 2026-04-30 by Plan 01.1-10 (see gap_closure_verification in frontmatter)
**Severity:** blocking (was)
**Source:** CONTEXT.md §Field Findings F-01 (commit `da7cacc`)
**Affected requirement:** R-7 (field_coverage gate)
**Discovered:** 2026-04-29 during BMW pilot manual gate (Plan 01.1-09 Task 4)

**Symptom:**
`DROM_BRAND_WHITELIST=bmw pnpm scrape:drom` ran for ~1 h 28 min walking BMW
brand → models → generation pages, then failed with:

```
HTTP 431 Request Header Fields Too Large
GET https://www.drom.ru/catalog/bmw/1-series/g_2007_23507/
```

The orchestrator emitted `report.json` with `final_status = "error"` and never reached
the per-complectation deep-dive loop, so `report.field_coverage` was not populated.
SPEC R-7 cannot be evaluated against this run.

**Root cause (verified):**
The cookie jar at `server/scrapers/shared/http.ts:20` accumulates every `Set-Cookie`
across the full crawl. Drom's feedback widget sets a cookie named `npsPayload` whose
value is a base64-encoded list of component IDs; drom appends another comp ID on every
`/catalog/*` page visit. The cookie value at failure time was ~8 KB. Combined with the
other ~10 drom cookies (`ring`, `segSession`, `PHPSESSID`, `cookie_cityid`,
`cookie_regionid`, `my_geo`, `dr_df`, `veryFirstHit`, `npsType`, `showNPS`), the
outgoing `Cookie:` header exceeded drom's nginx `large_client_header_buffers`. This is
NOT bot detection — a fresh `curl` with no cookies returns 200 on the same URL.

**Why test suite missed it:**
Phase 01.1's automated tests are all fixture-driven (no live HTTP).
`server/tests/http.test.ts` covers `pLimit(1)` serial-fetch and retry behaviour but
does not exercise long-session cookie accumulation. Phase 01's runs were shorter and
on shallower brand depths, so `npsPayload` never crossed the nginx threshold.

**Resolution scope (locked in CONTEXT.md D-09..D-13):**

The gap-closure plan must:

1. **Edit `server/scrapers/shared/http.ts`** — extend the existing `dromClient`
   `got.extend({ ... })` block with a `hooks.beforeRequest` array containing one
   hook that strips `npsPayload`, `npsType`, `showNPS` from the outgoing `Cookie`
   header on every drom request. The strip set lives as a module-scope
   `STRIP_COOKIES = new Set(['npsPayload', 'npsType', 'showNPS'])` constant.
2. **Add a regression test in `server/tests/http.test.ts`** — assert that when the
   cookie jar contains all three bloat cookies plus an affinity cookie (e.g.,
   `ring`), the outgoing `Cookie:` header on the next `dromClient` request contains
   `ring=...` but NOT `npsPayload=...`, `npsType=...`, or `showNPS=...`. No live
   network, no fixture HTML — use a got interceptor or an `afterResponse`/test-only
   hook to inspect the rendered header.
3. **Re-run** `DROM_BRAND_WHITELIST=bmw pnpm scrape:drom` end-to-end and verify
   `report.json.field_coverage` populates with all six rates ≥ 0.70 (closes Plan
   01.1-09 Task 4 / SPEC R-7).

**Out of scope** (do NOT include in the gap-closure plan — see CONTEXT.md F-01):

- Allowlist mode (denylist of three names is the smallest reasonable change).
- Replacing `tough-cookie` `CookieJar` (only the outgoing-header projection changes).
- Generic 431-retry logic (would mask future regressions; let drom changes fail loud).
- SPEC.md changes (R-5 / R-7 / R-8 stand — this is a defect, not a new requirement).

**Acceptance criteria for the gap-closure plan:**

- `grep -c "STRIP_COOKIES" server/scrapers/shared/http.ts` returns ≥ 1
- `grep -c "beforeRequest" server/scrapers/shared/http.ts` returns ≥ 1
- `grep -c "npsPayload\|npsType\|showNPS" server/scrapers/shared/http.ts` returns 3
- New regression test in `server/tests/http.test.ts` exists and passes
- `pnpm test` exits 0; `pnpm typecheck:server` exits 0
- BMW pilot run completes without HTTP 431; `data/scraped/drom/current/report.json`
  has `final_status === "ok"` and all six `field_coverage` rates ≥ 0.70
