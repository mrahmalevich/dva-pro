## Accomplishments

- **`renderFeaturesSections` shipped:** New JS function inside the embedded `<script>` block walks `features[]`, groups by section then subsection (insertion-ordered Map preserves drom source order), and emits `<div class="modal-section"><h3>…</h3><h4>…</h4><dl class="kv">…</dl></div>`. Returns empty string when features is empty / undefined / non-array — so legacy comp data renders byte-stable through the existing 6 typed sections.
- **Wired into `openCompModal`:** Single call site between the Шины renderKvSection and the `_extraction_errors` block — minimal surgery, the existing 6 typed sections (Идентификация, Цена, Двигатель и привод, Размеры, Комфорт, Шины) render unchanged.
- **Boolean glyphs:** `true → <span style="color: var(--ok);">✓</span>`, `false → <span style="color: var(--err);">×</span>` — uses the existing CSS variables for visual consistency with the rest of the viewer.
- **XSS hardening (T-01.2-08, T-01.2-09):** Every string output flows through `esc()` — section names, subsection names, feature labels, string values. Numeric values defensively go through `esc(String(n))`. Booleans never reach `esc()` (fixed literal HTML). Verified by an automated test that the literal payload `<script>alert(1)</script>` becomes `&lt;script&gt;alert(1)&lt;/script&gt;` in the rendered modal innerHTML.
- **9 puppeteer tests added:** Section h3 headings, subsection h4 headings, boolean ✓/× glyphs, numeric values verbatim, XSS escaping, source-order preservation, regression sentinel for the 6 typed sections, empty-features omission, undefined-features (legacy comp) omission.

## Decisions Made

See `key-decisions` in the frontmatter. The substantive ones:

1. **Puppeteer-driven tests, not static-HTML grep** — the modal HTML is rendered at click time by JS, not server-side. Asserting `>Экстерьер<` against static `index.html` would fail because that string only appears inside the JSON data block (as `"section":"Экстерьер…"`, no surrounding `>X<`). Puppeteer is already in dev deps (used by `bmw-pilot-viewer.test.ts`); each test costs ~400ms. Worth it: the tests verify actual rendered output, including correct DOM structure (`<h3>` vs `<h4>`).
2. **Models accessed via the embedded JSON data block, not via `window.models`** — the script-block declares `const models = data.models;` (script-scope, not window-attached). `openCompModal` IS on `window` because classic-script function declarations become globals; we read `models` back from `<script type="application/json">` and pass it explicitly.
3. **`globalThis as any` indirection inside `page.evaluate`** — the server tsconfig deliberately excludes the DOM lib to keep Node-side typing strict. The `any` cast is scoped to the browser-context callback (puppeteer serialises and runs it in Chromium where `document`/`window` exist at runtime). No global tsconfig change.

**2. [Rule 3 — Blocking issue] Initial test runs failed with `Cannot read properties of undefined (reading '0')` because `models` is script-scope `const`, not `window.models`**
- **Found during:** First `pnpm vitest run` after Task 2's initial test code was written.
- **Issue:** Inside the embedded viewer `<script>` block, `const models = data.models;` is script-scope (not on `window`). My initial puppeteer test code did `window.models[0]`, which was `undefined` at runtime.
- **Fix:** Read the model back from the `<script type="application/json">` data block (`document.getElementById('data').textContent` → `JSON.parse`) and pass it explicitly to `openCompModal`. `openCompModal` itself IS on `window` because classic-script function declarations become globals.
- **Files modified:** `server/tests/report-html.test.ts` (the `renderCompModalHtml` helper).
- **Verification:** All 9 new tests pass; existing 8 tests still pass.
- **Committed in:** `5693f72` (Task 2 commit — fix integrated before commit).

**3. [Rule 3 — Blocking issue] `pnpm typecheck:server` fails on `document` / `window` references — server tsconfig excludes DOM lib**
- **Found during:** `pnpm typecheck:server` after Task 2's first working test version.
- **Issue:** The server-side `tsconfig.server.json` has `lib: ["ES2023"]` only — no `DOM`. Adding `DOM` globally would mask real type errors elsewhere in the server-side code (Hono request handlers, Drizzle migrations, scrapers). Direct references to `document`/`window` inside `page.evaluate` callbacks would force a global lib change.
- **Fix:** Used `globalThis as any` indirection inside the `page.evaluate` callback only — the cast is scoped to the browser-context callback. Puppeteer serialises and runs it in Chromium where `document`/`window` exist at runtime; on the Node side, TypeScript only sees `any` once we cast.
- **Files modified:** `server/tests/report-html.test.ts` (the `page.evaluate` callback only).
- **Verification:** `pnpm typecheck:server` exits 0; all 9 new tests pass.
- **Committed in:** `5693f72` (Task 2 commit — fix integrated before commit).

**4. [Pattern note] Snapshot regeneration was deliberately bundled into Task 1's commit**
- **Trigger:** Task 1 acceptance criterion `pnpm vitest run server/tests/report-html.test.ts` passes; the snapshot test is one of the 8 existing tests.
- **Why bundled:** The snapshot captures the entire `index.html` byte stream INCLUDING the embedded JS source — adding `renderFeaturesSections` and the 1 wiring line necessarily changed the snapshot.
