# Phase 01.2 — Extend Complectation Fields (SCOPE seed)

## Phase Goal

Extend the drom comp scraper to capture all fields from drom's 8 main complectation tables. Use a **hybrid schema** (Strategy B): a small typed core for compute-relevant values + a `features` bag for everything else. Then re-scrape BMW X5 so the next snapshot has complete data.

## Why Urgent

Phase 01.1 produced a 38-gen / 477-comp BMW X5 dataset that is missing ~130 of the ~163 fields drom actually exposes. Adding it later means another ~5–7h re-scrape AND a schema migration on whatever was already imported into Phase 03's DB. Cheaper to do it now while pilot data is the only data on disk and `current/` symlink hasn't been repointed yet (the 01.1 pilot tripped the pricing coverage gate; current/ still points to the old, incomplete `2026-04-28T14-31-09Z` run that was wiped earlier today as part of quick task 260503-gja).

## Schema Strategy (B — Hybrid)

**Typed core additions to `Complectation` (`server/scrapers/shared/types.ts`):**

```ts
// Existing groups extended:
drivetrain.turbo: boolean | null
drivetrain.hybrid_type: 'mild' | 'plug-in' | 'full' | null
drivetrain.battery_capacity_kwh: number | null
drivetrain.electric_range_km: number | null
drivetrain.max_speed_kmh: number | null
drivetrain.acceleration_0_100_s: number | null
dimensions.payload_kg: number | null

// NEW group (chassis):
chassis.suspension_front: string | null
chassis.suspension_rear: string | null
chassis.brakes_front: string | null
chassis.brakes_rear: string | null
chassis.steering_type: string | null
```

**Features bag (catches everything else):**

```ts
features: Array<{
  section: string;        // ru: 'Экстерьер и внешнее оснащение'
  subsection: string | null;  // ru: 'Фары и оптика' | null
  label: string;          // ru: 'Светодиодные фары'
  value: string | boolean | number;  // true | 'опция' | 245
}>
```

Section/subsection labels stay in Russian — no RU→EN naming churn for ~130 features.

## Implementation Plan (6 tasks)

1. **Schema** — extend `types.ts` with typed slots + `features` array. Default `features = []` for back-compat with existing models.json.
2. **Parser** — generic section-walker in `parse-complectation-page.ts`. For each `<tr ...b-text_size_xxl><td colspan=2>SECTION</td>` block, walk until next section. Subsections: `b-text_size_xl`. Per-row normalisation: yes/no SVG → `boolean`; numeric+units → `number` (strip unit); "опция" badge → `string "опция"`. Map ~12 labels (turbo, hybrid_type, battery_capacity_kwh, electric_range_km, max_speed_kmh, acceleration_0_100_s, payload_kg, suspension_*, brakes_*, steering_type) to typed slots via regex; everything else → `features[]`.
3. **HTML viewer** — in comp-detail modal, after the existing 6 typed sections, render the 8 native drom sections from `features[]` grouped by section→subsection, each as a kv list. Booleans render with ✓/× glyphs.
4. **Coverage gate** — add `chassis ≥ 0.30` floor (sparse on legacy gens). Add `features_density ≥ 50` (avg features.length per comp; catches parser regression).
5. **Test fixtures** — re-validate against the 3 existing fixtures (`server/tests/fixtures/drom/complectation/{207354,252766,265067}.html`). Add 1 new fixture for a hybrid X5 (xDrive45e or similar) via `pnpm scrape drom --capture-fixture <comp_id>`. Update `parse-complectation-page.test.ts` assertions.
6. **Re-scrape** — wipe `data/scraped/drom/2026-05-03T05-05-16Z/`, `current` symlink, `.cursor.json`. Run `DROM_BRAND_WHITELIST=bmw DROM_MODEL_WHITELIST=x5 pnpm scrape:drom` (background, ~5–7h). On clean finish `current/` repoints automatically.
