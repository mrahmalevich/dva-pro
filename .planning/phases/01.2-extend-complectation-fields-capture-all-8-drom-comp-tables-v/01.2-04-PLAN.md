<objective>
Extend the per-field-group coverage gate (`server/scrapers/shared/coverage.ts`) to (a) include the new `chassis` group with a per-trim threshold of 4-of-5 non-null leaves and a per-run floor of 0.30 (acceptably sparse on legacy non-luxury gens), and (b) add a parser-regression detector via `features_density` — the average length of `complectations[i].features` across all comps, with a floor of 50.

Why these floors:
- **chassis ≥ 0.30:** drom only populates suspension/brake type strings on premium / late-model trims; pre-2010 X3/Lada-tier comps frequently have all-null chassis. 0.30 means roughly 30% of comps have a covered chassis group — a regression to 0 means the section walker missed `Подвеска / Ходовая часть` entirely.
- **features_density ≥ 50:** if the BMW X5 G05 fixture surfaces ~150 features and older gens have ~80, an average ≥ 50 is comfortably above what a single-section regression would produce (a complete walker failure → 0; missing one section → ~120). 50 is a robust low watermark.

Output: Extended computeFieldCoverage + meetsCoverageGate + 8+ new test assertions.
</objective>

             identity: 0, pricing: 0, drivetrain: 0, dimensions: 0,

         const featureLengths = trims.map((t) => Array.isArray(t.features) ? t.features.length : 0);

         return {

           pricing: round2(trims.filter((t) => trimMeetsThreshold(t, 'pricing')).length / total),

           tires: round2(trims.filter((t) => trimMeetsThreshold(t, 'tires')).length / total),
