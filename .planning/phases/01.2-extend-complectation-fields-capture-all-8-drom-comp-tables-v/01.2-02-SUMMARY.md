## Decisions Made

See `key-decisions` in the frontmatter. The substantive ones:

1. **Generic walker over per-label extraction** — drom shows ~167 rows per comp page; the per-label approach Plan 01.1 used would balloon to ~130 new extractor functions. The walker is single-implementation, single-test-target, and gracefully handles new sections drom may add later.
2. **First-mapping-match-wins typed-slot dispatch** — eliminates per-slot if-trees and per-row regex retesting. Bounded by 12 mappings × ~167 rows = ~2k regex applications per comp, all anchored.
3. **Em-dash → null and dropped from features** — drom uses `—` for "field not applicable to this trim". Without this filter, the features bag would balloon to ~250 entries per comp with ~100 of them being meaningless `value: '—'` strings.
4. **False-SVG test skipped, not deleted** — preserves the documentation of expected walker behaviour; CI auto-runs the test if a fixture with #no cells is captured later.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 — Bug] Plan-specified `xlink:href` selector doesn't work in cheerio v1.2**

- **Found during:** Task 2 (initial walker smoke test with fixture 207354 — features count came back at ~63 instead of expected ~137; 0 boolean true values despite 75 #yes SVG cells in the fixture).
- **Issue:** The plan's literal selector `use[xlink\\:href="#yes"]` and attr lookup `useEl.attr('xlink:href')` both returned 0 matches against the captured fixture. Empirical inspection (`$('use')[0].attribs`) showed cheerio v1.2 normalises namespaced SVG attributes to the local name only — i.e. `xlink:href="#yes"` in source HTML becomes `href="#yes"` in cheerio's parsed DOM.
- **Fix:** Selector → `use[href="#yes"], use[href="#no"]`; attr lookup → `useEl.attr('href')`. Inline JSDoc documents the cheerio v1.2 quirk. After fix: 74 boolean-true entries on fixture 207354 (75 yes-SVG cells minus 1 mapped to drivetrain.turbo) ✓.
- **Files modified:** `server/scrapers/drom/parse-complectation-page.ts`.
- **Verification:** `features.filter(f => f.value === true).length === 74` on fixture 207354.
- **Committed in:** `068dbab` (Task 2).

**2. [Rule 1 — Bug] Plan's typed-slot regex `^турбонаддув$|^наддув$` doesn't match the actual drom label**

- **Found during:** Task 2 smoke (drivetrain.turbo came back null despite the row being clearly visible in the fixture).
- **Issue:** The drom DOM uses label "Нагнетатель" (yes/no) for the boolean turbo cell, not "Турбонаддув". "Турбонаддув" doesn't appear anywhere in the fixture HTML. The same row also has a follow-up "Тип нагнетателя" → "Турбина" (string) which stays in features[].
- **Fix:** Regex extended to `/^нагнетатель$|^турбонаддув$|^наддув$/`. Plan-specified labels retained as fallbacks for older drom layouts.
- **Files modified:** `server/scrapers/drom/parse-complectation-page.ts`.
- **Verification:** `record.drivetrain.turbo === true` on fixtures 207354, 252766, 265067.
- **Committed in:** `068dbab` (Task 2).

**3. [Rule 1 — Bug] Plan's payload regex `^грузоподъ[её]мность` doesn't match "Максимальная грузоподъёмность"**

- **Found during:** Task 2 smoke (dimensions.payload_kg came back null).
- **Issue:** drom's actual label has the prefix "Максимальная" — the plan's `^` anchor rejects it.
- **Fix:** Regex relaxed to `/(^|\b)(максимальная )?грузоподъ[её]мность|^полезная нагрузка/`. The optional prefix is bounded; no backtracking risk.
- **Files modified:** `server/scrapers/drom/parse-complectation-page.ts`.
- **Verification:** `record.dimensions.payload_kg === 675` on fixtures 207354, 252766; `615` on 265067.
- **Committed in:** `068dbab` (Task 2).

**4. [Rule 1 — Bug] cheerio v1.2 dropped the `cheerio.Element` namespace export**

- **Found during:** Task 1 (initial typecheck after adding `td: cheerio.Cheerio<cheerio.Element>` parameter type per plan).
- **Issue:** TS error: `Namespace 'cheerio' has no exported member 'Element'`. cheerio v1.2 only re-exports `Cheerio`, `CheerioAPI`, `CheerioOptions`, `HTMLParser2Options` from its public surface; the underlying `Element` type lives in `domhandler` (transitive dep, not directly resolvable).
- **Fix:** Added `type CheerioWrapper = ReturnType<cheerio.CheerioAPI>` alias — `$('td')` returns a `Cheerio<Element>` for any selector, so this matches the walker's parameter shape without pulling in `domhandler` as a direct dep. Inline comment explains the rationale for future scrapers.
- **Files modified:** `server/scrapers/drom/parse-complectation-page.ts`.
- **Verification:** `pnpm typecheck:server` exits 0.
- **Committed in:** `06c5c0c` (Task 1).
