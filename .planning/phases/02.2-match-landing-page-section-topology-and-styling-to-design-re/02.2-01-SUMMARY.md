# Phase 02.2 Plan 01: InTransit Data Layer + Section Component Summary

**One-liner:** CRM data layer extended with InTransitItem type + 4 fixture cars, plus a new InTransit section component rendering them as a dense 4-column card grid.

## What Was Built

### Data Layer (Task 1)
- **`src/crm/types.ts`**: Added `InTransitItem` interface (id, brand, model, country, status, statusLabel, eta, priceLandedRu, accent) and `inTransit: InTransitItem[]` field on `CrmState`.
- **`src/crm/seed.ts`**: Added 4 fixture entries — BMW X5 xDrive40i (KR, in-transit), Lexus LX 600 (JP, customs), Mercedes-AMG G63 (KR, in-transit), Genesis GV80 3.5T (KR, ready). SEED.reviews already had 3 entries.
- **`src/crm/CrmProvider.tsx`**: Added `inTransit: parsed.inTransit ?? SEED.inTransit` to `loadInitialState` return object — no new mutators.

### Section Component (Task 2)
- **`src/sections/InTransit.tsx`**: Exports `InTransit` component. Reads `state.inTransit` via `useCrm()`. Renders up to 4 horizontal cards in a CSS grid. Each card: `CarPlaceholder height={180}`, flag + status `Chip` row, brand/model text block, price + ETA footer. Cards separated by single border-right suppression to achieve seamless panel effect. `Reveal` animation with 80ms stagger per card. Early-returns `null` if array is empty.

## Deviations from Plan

None — plan executed exactly as written.

The only minor adjustment: the plan's InTransit.tsx template computed `statusIcon` inline as a ternary string cast, which TypeScript would widen to `string` rather than `IconName`. Fixed by assigning to a `const statusIcon: IconName` variable before JSX — this is a correctness fix (Rule 2: type safety for Icon's required `name` prop), not a behavioral change.
