<decisions>
## Implementation Decisions

### Section ordering (locked from design-reference.png)

- **D-01:** New `src/pages/Site.tsx` render order is: `Hero → Marquee → LeadMagnet (quiz teaser slot) → Catalog → Process (4-step horizontal) → InTransit (Реальные авто в пути) → Reviews → CtaShipFromAnywhere (Привезём…) → Faq → Footer + FloatingDock`. Founders is removed from the home route. FeedStrip is removed from the home route (or repurposed into `InTransit`).
- **D-01a:** Faq stays in place at the bottom — design reference doesn't show it explicitly but it's always-on for this audience. Rationale: deleting Faq is out of scope (#3 phase boundary) and keeping it is the conservative default.

### Restructuring decisions

- **D-02:** **Process** is restructured from 6 vertical steps (current `src/sections/Process.tsx`) to **4 horizontal steps** matching the design ("Заявка → Подбор → Покупка → Доставка"). The new component renders a 4-column horizontal grid on desktop (≥980 px), each step a numbered badge (01..04) + label + 1-line description, with the connecting hairline between steps. Mobile breakpoint (≤720 px) collapses to vertical stacking — must not regress.
- **D-02a:** The 4 steps' canonical labels are: `01 Заявка`, `02 Подбор`, `03 Покупка`, `04 Доставка`. Each gets a 1-line description copied from the existing 6-step content (closest semantic mapping). Old 6-step descriptions are condensed: steps 1-2 → "Заявка"; steps 3-4 → "Подбор"; steps 5 → "Покупка"; steps 6 → "Доставка".
- **D-02b:** The sticky right-rail preview card from the current Process is dropped — design reference does not show one. Acceptable scope reduction.

- **D-03:** **LeadMagnet** is moved from its current position (between Process and Reviews) to a quiz-teaser slot directly after Marquee, before Catalog. Its component implementation is unchanged — only its position in `Site.tsx` changes. Heading remains "Подборка из 6–8 авто под ваши параметры" (close enough to design's "Подберите авто за 2 минуты" — exact copy match deferred).

- **D-04:** **Founders** is removed from the home route. The component file stays in `src/sections/Founders.tsx` (unmodified) for potential reuse in a future "About" page. Just remove the import and JSX from `Site.tsx`.

- **D-05:** A new **InTransit** section (`src/sections/InTransit.tsx`) is created. Renders 4 cards in a horizontal grid with: car thumbnail, model name, country-of-origin flag pill, status pill ("В пути", "На таможне", "Готов к выдаче"), price under-key estimate. Reads from a new `state.inTransit[]` array on `CrmProvider` — fixture-seeded for v1. FeedStrip is removed from the home route (its "Лента событий" feed is too generic for this slot — repurpose deferred).
- **D-05a:** InTransit fixture cars are 4 entries: BMW X5, Lexus LX 600, Mercedes-AMG G63, Genesis GV80 — a recognizable mix matching the brand row in Hero. Status pills use existing `Chip` atom + `Icon` for visual continuity.

- **D-06:** A new **CtaShipFromAnywhere** section (`src/sections/CtaShipFromAnywhere.tsx`) is created. Dark background, large outline-italic headline matching design ("Привезём вам автомобиль из&nbsp;<em>любого порта</em> мира"), short body line, single primary button (`Открыть квиз`) wired to `onOpenQuiz`. Visual style mirrors Hero's hero-block treatment (gradient background, coral accent) for visual bookend. Renders before Faq.

- **D-07:** **Reviews** currently early-returns `null` when `state.reviews.length === 0`. Seed 3 fixture reviews in `CrmProvider` so the section renders visibly. Reviews fixtures: 3 entries with name, location, snippet, avatar (or generated initials), and a video-thumbnail placeholder. No real video integration — `src` is a placeholder image, `playable: false` flag.

### Visual fidelity / golden test

- **D-08:** Re-tune `DIFF_THRESHOLD` in `server/tests/landing-page-golden.test.ts` AFTER restructure lands. Current value is `0.28` (set by Phase 02.1). Expected post-02.2 floor is unknown — measure empirically via `npm test`, then set threshold to `ceil((measured + 0.03) × 100) / 100` (same formula as Phase 02.1). Document the new value in 02.2-VERIFICATION.md.
- **D-08a:** If post-restructure floor regresses (i.e., higher than 0.28), threshold may rise to keep test green. This is acceptable: section topology fidelity > pixelmatch numeric. Mark as honest tradeoff in VERIFICATION.md.

### Mobile guard

- **D-09:** Mobile breakpoint blocks (≤720 px in `src/styles/global.css`) MUST remain byte-identical to current state, except where new sections inherit canonical mobile rules naturally. Specifically: `min-height: auto !important` Hero override, mobile font sizes, and stacking direction overrides preserved. `git diff -- src/styles/global.css` post-execution must show only Process-related desktop selectors changing (if any), or no changes at all if Process gets inline styles.

### Fixture seeding

- **D-10:** All new fixture data (in-transit cars, review entries) lives in the same module that currently seeds `state.feed`/`state.reviews` in `CrmProvider`. No separate JSON files. Rationale: matches existing pattern, no new file types to maintain.

### Claude's Discretion

- Exact copy strings for new sections (InTransit cards, final CTA body line) — Claude picks, with the constraint that they must be plausible Russian-language landing-page copy in the existing voice.
- Exact pixel values for new section paddings — Claude picks from the existing canonical scale (`var(--ink)`, `padding: 72px 0` from Phase 02.1, etc.).
- Whether to keep `FeedStrip.tsx` file or delete it — Claude picks delete-from-route, keep-file (analogous to Founders).
- Inline styles vs. tokens for new sections — Claude follows the existing pattern (mostly inline; canonical scale values).

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- **`Chip`, `Icon`, `Reveal`, `Live`, `CarPlaceholder`, `FlagFor`** atoms already cover all visual primitives the new sections need. New sections should compose these, not introduce new atoms.
- **`useCrm()`** already exposes `state.reviews`, `state.feed`. Extend with `state.inTransit` for the new section.
- **`onOpenQuiz`** prop pattern is already wired through Hero/Catalog/Process/LeadMagnet — new CtaShipFromAnywhere section uses the same prop.

### Established Patterns
- All sections use **inline styles** + canonical CSS variables (`var(--ink)`, `var(--coral)`, `var(--mute)`, `var(--line)`). No CSS modules, no styled-components.
- Section vertical rhythm: `padding: 72px 0` desktop (from Phase 02.1), with section-specific tightening via inline `marginBottom`/`marginTop` overrides.
- Cards: `background: '#0F0F0E', border: '1px solid var(--line)', padding: 24` is the canonical card surface.
- Numbered markers: `<div className="num-marker">NN / Section</div>` is the established pattern for section numbering (used by Reviews already).

### Integration Points
- `Site.tsx` imports + JSX is the single integration touch-point for ordering changes.
- `CrmProvider` exports a context with `state` — fixture data added there is consumed by `useCrm()` everywhere.
- The golden test `landing-page-golden.test.ts` is the integration acceptance gate.

</code_context>

<specifics>
## Specific Ideas

- The "Привезём вам автомобиль из любого порта мира" final CTA should visually echo the Hero block — coral glow, gradient, outline-italic emphasis — to act as a bookend. The user will scroll back to the top after the CTA or hit the floating quiz button.
- The 4-step horizontal Process is a **layout** restructure; the existing 6-step content semantic groupings should be folded into 4. Don't drop information; condense it.
- Reviews fixtures should look real (recognizable Russian first names + cities; plausible 1-2-sentence quotes). Avoid lorem ipsum.
- InTransit cards should mirror Catalog card density visually — same `CarPlaceholder height={180}`, same border treatment — so the page reads as visual rhythm.

</specifics>
