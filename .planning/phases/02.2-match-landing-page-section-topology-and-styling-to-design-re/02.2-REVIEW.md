# Phase 02.2: Code Review Report

**Reviewed:** 2026-05-07
**Depth:** standard
**Files Reviewed:** 8
**Status:** issues_found

## Summary

The phase delivers what it promises structurally — `Site.tsx` now matches the design-reference order, `Process.tsx` was correctly collapsed from a 6-step interactive panel to a 4-cell horizontal grid, and the `inTransit` data path is wired cleanly from `types.ts → seed.ts → CrmProvider.loadInitialState → InTransit.tsx`. Type safety is preserved, and the localStorage migration path is safe (existing users get `SEED.inTransit` via the `??` fallback).

However, two real defects ship with this code:

1. **Broken navigation anchors** — `Site.tsx` no longer renders the `Founders` section, but `Nav.tsx:8` and `Footer.tsx:38` still link to `#founders`. Clicking "Ребята" in the top nav or footer scrolls nowhere. This is a user-facing regression introduced by this phase, even though those nav files were not edited (the contract between page composition and nav anchors is broken).
2. **InTransit has no mobile breakpoint** — `Process.tsx` correctly added a `@media (max-width: 720px)` stack-to-1-col rule, but the structurally-identical `InTransit.tsx` did not. On mobile, four 80–100px-wide cards squish horizontally with `CarPlaceholder` height=180 — directly violating phase rule D-09 (mobile breakpoint preservation).

Beyond those, several quality issues: an over-broad descendant selector in `Process.tsx`'s mobile CSS, an asymmetric drop-to-null pattern in `InTransit.tsx` vs. `Process.tsx`'s static fallback, a tightened test headroom (1.82pp vs the prior 3pp band) that increases flake risk, and two orphan section files (`FeedStrip.tsx`, `Founders.tsx`) now unused but still on disk.

## Blocker Issues

### BL-01: Nav and Footer link to deleted `#founders` anchor

**File:** `src/components/Nav.tsx:8`, `src/sections/Footer.tsx:38`
**Issue:** This phase removed `<Founders />` from `Site.tsx` (along with `<FeedStrip />`), but the `Nav` link list and the Footer "Сайт" column still contain `['Ребята', '#founders']`. The `#founders` element no longer exists in the DOM, so:
- Desktop: clicking "Ребята" in the top nav does nothing (browser scrolls to top of `#` since target is missing).
- Mobile: the menu link does nothing and the user has no recovery path.
- Footer column has the same dead link.

This is a user-visible broken-link regression introduced *by this phase* even though the nav/footer files were not in the diff — the implicit contract (nav anchors must reference rendered sections) was broken. It is a BLOCKER because navigation is core UX surface and the fix is a one-line change.

**Fix:** Remove the entry, or repoint to a still-rendered section. Suggested: drop `'Ребята'` (founders content has been absorbed into the Hero/Catalog narrative per the redesign) or repoint to `#cta-ship-from-anywhere` if a "founders" stand-in is desired.

```tsx
// src/components/Nav.tsx

  ['Процесс', '#process'],
  // ['Ребята', '#founders'],  // ← REMOVED: section dropped in 02.2; restore when Founders returns
  ['Отзывы', '#reviews'],
  ['FAQ', '#faq'],
```

Apply the identical edit to the inline list in `src/sections/Footer.tsx:38`.

### BL-02: `InTransit.tsx` ships with no mobile breakpoint — violates phase rule D-09

**File:** `src/sections/InTransit.tsx:21-25`
**Issue:** The grid uses `gridTemplateColumns: \`repeat(${Math.min(state.inTransit.length, 4)}, 1fr)\`` with no `@media` override. With the seeded 4 items and viewport widths < 720px, four cards squeeze into a row, each ~80–95px wide, with a fixed `CarPlaceholder height={180}` and `padding: 24` — chips wrap to multiple lines, brand label overflows, and the `priceLandedRu` / `eta` row collapses unreadably.

The phase context explicitly calls out: *"Mobile breakpoint preservation is a hard rule (D-09) — flag any mobile-regression risk."* The structurally-identical `Process.tsx` correctly added a stack-to-1-col rule for `<= 720px`. `InTransit.tsx` did not.

**Fix:** Mirror the `Process.tsx` mobile pattern. Move the grid to a className and add a scoped `<style>` block (or extract both to a shared CSS file):

```tsx
<section id="in-transit" style={{ background: '#0a0a09', color: '#fff' }}>
  <div className="container">
    {/* …header… */}
    <div
      className="in-transit-grid"
      style={{
        display: 'grid',
        gridTemplateColumns: `repeat(${Math.min(state.inTransit.length, 4)}, 1fr)`,
        gap: 0,
      }}
    >
      {/* …cards… */}
    </div>
  </div>
  <style>{`
    @media (max-width: 720px) {
      #in-transit .in-transit-grid { grid-template-columns: 1fr !important; }
      #in-transit .in-transit-grid > * > div { border-right: 1px solid var(--line) !important; }
    }
  `}</style>
</section>
```

Note: at single-column the per-card `borderRight: 'none'` (line 37, applied for all-but-last) must be re-enabled, otherwise cards lose their right edge entirely on mobile. The `Process.tsx` rule strips right borders (correct because each card has none on the left); `InTransit.tsx`'s cards have a full `border` on each side, so the mobile rule is the inverse — restore the right border.

## Warning Issues

### WR-01: Over-broad descendant selector in Process.tsx mobile CSS

**File:** `src/sections/Process.tsx:75`
**Issue:** The mobile rule `#process .process-grid > * > div { border-right: none !important; }` matches the **immediate first** `div` inside each `Reveal` wrapper — currently the card root, which is what's intended. But `> *` (Reveal) `> div` (card) only targets the card root, not its inner descendants — so today this works. The fragility: if anyone later wraps the card in another element, or adds a sibling `<div>` inside Reveal, the selector silently misses or over-matches. Also, the `!important` is needed only because the inline `borderRight` is computed in JSX; the cleaner fix is to put the desktop border in CSS too.

**Fix:** Use a stable class selector instead of structural `> * > div` traversal:

```tsx
// On the inner card div:
<div className="process-cell" style={{ /* drop borderRight from inline; move to CSS */ }}>

// In <style>:
@media (max-width: 720px) {
  #process .process-grid { grid-template-columns: 1fr !important; }
  #process .process-cell { border-right: none !important; }
}
```

### WR-02: Asymmetric data-defensive behavior between InTransit and Process

**File:** `src/sections/InTransit.tsx:7`, `src/sections/Process.tsx:11-21`
**Issue:** `InTransit` returns `null` if `state.inTransit` is empty/missing — the section disappears silently, leaving a layout hole and breaking the design-reference's narrative beat. `Process`, by contrast, always renders because of `FALLBACK_STEPS`, even if `state.timeline` is empty. Inconsistent robustness for two sections that occupy structurally similar slots in the new layout. A user who clears `inTransit` in the admin (or whose stale localStorage drops the key) will see the page jump from Process directly to Reviews with no visual indication.

**Fix:** Either (a) add a hardcoded `FALLBACK_TRANSIT` array of 4 placeholders mirroring `Process.tsx`'s pattern, or (b) document explicitly in a comment that `InTransit` is a CRM-only section that is allowed to disappear (and confirm the design reference accommodates this gracefully).

### WR-03: Test threshold headroom narrowed from 3pp to 1.82pp — flake risk

**File:** `server/tests/landing-page-golden.test.ts:20`
**Issue:** Previous baseline: post-Wave-1 floor 24.52%, threshold 0.28 → 3.48pp headroom. New baseline: post-02.2 floor 26.18%, threshold kept at 0.28 → 1.82pp headroom. The test does subpixel font rendering on a headless Chromium and resizes from 1280×N down to 605×1280 with `fit: 'fill'` (lossy distortion). Cross-machine variance on font rendering or system font fallback alone can move the diff ratio by ±1–2pp. With under 2pp headroom, the test is more likely to flake on developer machines or CI runners with even slightly different font caches.

**Fix:** Either (a) bump threshold to 0.30 to restore ~3pp headroom (low cost — 28% → 30% is still tight enough to detect structural regressions), or (b) document an explicit policy that flaky failures on this test are expected and require running locally to confirm; this should live in the test file or `02.2-VERIFICATION.md`.

```ts
const DIFF_THRESHOLD = 0.30; // 30% — empirical post-02.2 floor 26.18% + 3.82pp headroom
```

### WR-05: `CarPlaceholder` label can overflow narrow `InTransit` cards

**File:** `src/sections/InTransit.tsx:44`
**Issue:** `<CarPlaceholder label={it.brand} ...>` passes raw brand strings like `'Mercedes-AMG'` (12 chars). `CarPlaceholder` (`atoms.tsx:143`) renders the label at `fontSize: 28, fontWeight: 900, fontStyle: 'italic'` absolute-positioned bottom-left with no truncation, max-width, or auto-shrink. At desktop 1280/4 ≈ 320px card width that's fine; once mobile is fixed (BL-02) it stacks to ~340px which is also fine; but at intermediate widths (≈768–900px) where the grid stays at 4 cols, the label can overflow the placeholder rectangle and clip into the chip row above.

**Fix:** Either pass shorter labels (`it.brand.split('-')[0]` for AMG/Mercedes-AMG cases) or extend `CarPlaceholder` to truncate / shrink the label. Lowest-impact fix — pass a truncated label inline:

```tsx
<CarPlaceholder
  label={it.brand.length > 8 ? it.brand.slice(0, 8) + '…' : it.brand}
  accent={it.accent}
  height={180}
/>
```

### WR-06: `loadInitialState` `try/catch` swallows JSON parse errors silently

**File:** `src/crm/CrmProvider.tsx:23`
**Issue:** Pre-existing pattern, but worth flagging now that the surface area expanded to `inTransit`: when `JSON.parse` throws on corrupted localStorage, the `catch {}` swallows the error and silently rolls back to `SEED`. Users with corrupted state lose any local edits without any signal — neither in console nor UI. Now that `inTransit` has been added to the persisted shape, the silent-rollback blast radius grew. A minimal log helps debugging without changing behavior.

**Fix:**
```ts
} catch (e) {
  if (typeof console !== 'undefined') console.warn('[crm] localStorage parse failed; reverting to seed', e);
  return SEED;
}
```
