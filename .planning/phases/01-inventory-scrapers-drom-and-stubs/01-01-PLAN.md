| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Tampering | Supply chain — `pnpm install` | mitigate | pnpm has `verify-store-integrity: true` by default (per pnpm 10.x); pinned `packageManager: "pnpm@10.29.2"` so all environments use the same package-manager version. Lockfile committed; CI uses `--frozen-lockfile`. |
| T-01-02 | Tampering | sharp native binary postinstall | accept | sharp is a top-100 npm package with reproducible binaries (libvips); risk is industry-wide and mitigation (e.g., binary verification) is out of Phase 1 scope. Pin major version `^0.34.5` to lockfile. |
| T-01-03 | Information Disclosure | Accidental commit of `.env` or runtime data | mitigate | `.gitignore` excludes `.env`, `.env.local`, `data/scraped/**/{models.json,images/,*.webp,report.json,.cursor.json,current,*.xml}` (Task 3). Phase 1 needs ZERO secrets (RESEARCH.md line 871) — any `.env` present is unexpected. |
| T-01-04 | Denial of Service | Vite SPA build broken by pnpm migration | mitigate | Task 1 verifies `pnpm build` exits 0 before completing; commit only after smoke green (RESEARCH.md Risk 3). |
| T-01-05 | Repudiation | Lockfile drift between dev and CI | mitigate | `packageManager: "pnpm@10.29.2"` pin + `pnpm-lock.yaml` committed + `pnpm install --frozen-lockfile` is the contract for CI. |
</threat_model>
